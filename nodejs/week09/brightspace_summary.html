Week 9: A Face on mflix, then Hardening the API

Last week we learned EJS from an empty folder: templates, escaping, loops, partials and forms, all on small in-memory examples. This week we put those templates on the real thing. We take the week 7 movies API and give it a face: a searchable, paged movie list rendered from MongoDB, a detail page, add/edit/delete forms that use the API's own validation rules, and a login that uses a session cookie instead of a token, with roles and protection against cross-site request forgery. The JSON API keeps working alongside the pages, unchanged. Then a wrap-up: a review game, a debate on server- vs client-side rendering (EJS, PHP, React), and a levelled lab where you build your own movie pages with comments.

The rest of the week is about hardening. We look at Node modules and how require() / import organize a growing codebase, then operational visibility: Morgan for HTTP request logging and express-winston for structured application logs, so that when something breaks you have evidence. Next, JWT enforced as middleware on a real REST API. Then CI/CD: a GitHub Actions workflow that checks out, installs and deploys a Node API to an Azure Web App on every push to main. We close on the OWASP Top 10 (2021), working through all ten risks and the defence for each.

What we'll cover

  • The same Express app answering with JSON for the API and HTML for the pages
  • Re-using validation rules so a form and the API can't disagree
  • Sessions with express-session: cookies vs JWTs, and when to use each
  • Roles on pages, res.locals, flash messages, and CSRF tokens
  • Server-side rendering (EJS, PHP) vs client-side rendering (fetch, React): trade-offs
  • Lab: paging, comments from a second collection, and a reusable partial
  • Node modules: require() vs. ES import, and built-in modules like fs and http
  • HTTP request logging with Morgan; structured application logging with express-winston
  • JWT middleware on a RESTful API, and the claims a token carries
  • CI/CD: what continuous integration and deployment automate, and why it catches issues early
  • GitHub Actions deploying a Node.js API to an Azure Web App on push to main
  • OWASP Top 10 (2021), A01–A10: broken access control, cryptographic failures, injection, insecure design, security misconfiguration, vulnerable components, authentication failures, integrity failures, logging failures, and SSRF
