Week 11: Full-Stack MERN

This week everything from the term comes together in one stack: MongoDB, Express, React and Node. A MERN app is two programs that agree on a contract: an API that answers with JSON, and a React app that asks for data and shows it. You already know the pattern (ask for data, then build the page from it) from fetch() last year and from PHP and EJS this year. What's new is that the two halves are two separate projects, each with its own folder, package.json and .env.

In the first class the API is ready for you (nodejs/week11/api), and you build the app half from nothing: scaffold a new React app with Vite in react/app, set up Vite's proxy to the API, then fetch the movies with useEffect and show them in a list.

In the second class we keep building that same app, and use the rest of what the API can do. We start with UML diagrams of where we are and what we're adding. Then a search form that sends the search to the API, a DELETE route you add to the API and a Delete button on every movie, and an Add a movie form in a Bootstrap modal (the code is given; we read it together). We finish with what's still missing: right now anyone can add or delete movies, so next class the API learns who you are.

What we'll cover

  • The MERN stack end to end: what runs in the browser, in Vite, in Express and in MongoDB
  • API and APP as two projects: separate folders, deployed on their own, joined only by the API contract
  • Scaffolding a React app with Vite in its own container; vite.config.js (host, polling, the /api proxy)
  • useEffect + fetch(), checking res.ok, and rendering a list with keys
  • UML deployment, class and sequence diagrams of our app
  • A search form: controlled inputs, onSubmit, the dependency array, and encodeURIComponent
  • DELETE /api/movies/:id: route parameters, ObjectId.isValid, deleteOne, and the status codes 204, 400 and 404
  • Updating state the React way: a new array with filter and the spread operator
  • A Bootstrap modal controlled by React state, and handling every answer from the API (201, 400, 502, no answer)
  • Why validation and security checks belong on the server, not only in the browser
